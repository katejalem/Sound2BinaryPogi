06

Explain It

Short answers

1 How does your app change a sound wave into binary? Name the three steps.

My converter breaks the process into three stages. Sampling measures the wave's height at evenly spaced moments within one period. Quantization then maps each measured height onto the nearest whole level, where the allowed levels run from 0 up to 2^bits - 1. Encoding finishes the job by turning every level into a binary string with padStart, so each value ends up with exactly bits digits, leading zeros included.

2 Run Test A again with 2 bits, then 6 bits. Which gives more detail about the wave, and why?

Test A with 6 bits is clearly the more detailed one. The bit count decides how many levels are available: 2 bits gives just 4 levels, while 6 bits opens up 64. With so few levels, each sample has to be pushed to a level that may sit far from its real height, so the shape of the wave gets distorted. The finer 64-step ladder keeps every value much closer to where the wave actually was.

3 Which test has the longest wavelength? How is wavelength connected to frequency?

Among the three tests, Test B has the longest wavelength, measuring about 1.72 m. The two quantities are inversely proportional, linked by wavelength = 343 / frequency. That means doubling the frequency cuts the wavelength in half, and halving the frequency doubles it. Since Test B runs at only 200 Hz, the slowest of the set, its wave stretches out the farthest.

4 What was the hardest stage to build, and how did you fix it?

Quantization gave me the most trouble. The heights arriving from the sine function range from -1 to +1, but the levels must be whole numbers starting at 0, and early attempts produced values that fell outside the valid range or landed unevenly at the endpoints. I solved it with the formula level = round(((height + 1) / 2) * (levels - 1)), which always lands inside 0 to levels - 1. I then locked it down by checking the known case of frequency 1000, amplitude 1, samples 4, bits 2, which must return 10 11 10 00, and I used padStart so the shorter binary values kept their leading zeros.
